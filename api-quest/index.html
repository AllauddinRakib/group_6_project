Welcome, Explorer!

An API (Application Programming Interface) lets programs talk to each other. When your app asks a server for data, it sends an HTTP request, and the server sends back an HTTP response, usually as JSON.

HTTP Methods

  • GET — read data
  • POST — create data
  • PUT / PATCH — update data
  • DELETE — remove data

Status Codes

  • 2xx — success (e.g. 200 OK, 201 Created)
  • 3xx — redirection
  • 4xx — your fault (400, 401, 404)
  • 5xx — server's fault (500, 503)

Anatomy of a Request

GET /api/users/42 HTTP/1.1
Host: example.com
Authorization: Bearer <token>
Accept: application/json

A JSON Response

{
  "id": 42,
  "name": "Ada",
  "role": "admin"
}

REST Principles

  • Resources live at URLs (/users/42)
  • Use the right method for the action
  • Stateless — each request stands alone
  • Use status codes meaningfully

Auth Basics

  • API Key — simple shared secret
  • Bearer Token — sent in Authorization
  • OAuth 2.0 — delegated access
  • Never hard-code secrets in client code
